# ТЗ: Монетизация Modul3D

Статус: черновик, согласован с пользователем 2026-08-27. Отражает решения
из обсуждения — не финальная спецификация для разработки, а основа для
детализации перед началом каждого этапа.

Текущая база: MVP v189, чисто клиентское приложение без сборщика и без
сервера (см. `CLAUDE.md`). Монетизация требует добавить серверную часть —
это первый сервер в проекте вообще.

## 1. Разделение функций

| Бесплатно | Платно |
|---|---|
| 3D-конфигуратор, ручной ввод параметров | Экспорт документов: Excel, DXF/CSV, (в будущем) PDF |
| Пресеты готовых модулей | Загрузка эскиза → распознавание ИИ |
| Расчёт и просмотр спецификации/стоимости на экране | |

Расчётное ядро (`engine.js`, `specification.js`) и 3D-вьюер (`viewer.js`)
остаются полностью клиентскими и офлайн — они не меняются.

## 2. Модель оплаты

- **Подписка** (месяц/год) — открывает безлимитный экспорт документов.
- **Токены** — отдельный баланс на аккаунте, списывается только за вызовы
  ИИ-распознавания эскиза (т.к. каждый вызов реально стоит денег в Anthropic
  API — ключ будет привязан к аккаунту разработчика, не пользователя).
- Конкретные цифры (цена подписки, стартовый запас токенов, стоимость
  одного вызова эскиза в токенах) — не зафиксированы, задаются как
  настройки на этапе реализации Этапа 1.

## 3. Приём платежей

- Старт: глобальный приём через Stripe/Paddle (или аналог) — юрлицо/
  подключение не в РФ.
- РФ-приём (ЮKassa/CloudPayments/Тинькофф) — отдельный, более поздний этап,
  т.к. Stripe/Paddle не работают с российскими юрлицами и картами.

## 4. Технический подход к защите платных функций

- **Экспорт документов — жёсткий гейт.** Сейчас `export.js` и `cnc.js`
  генерируют файлы полностью в браузере — код открыт (нет сборщика/
  минификации), клиентскую проверку легко обойти. Решение: параметры модели
  уходят на сервер, файл (.xlsx/.dxf/.csv) генерируется там же и отдаётся
  клиенту только при активной подписке. Логика генерации документов
  переезжает на сервер.
- **ИИ-эскиз — через сервер.** Сейчас `sketchAI.js` вызывает Anthropic API
  прямо из браузера с ключом, который вводит сам пользователь (bring-your-
  own-key). После монетизации: клиент отправляет картинку на свой сервер,
  сервер проверяет баланс токенов пользователя, сам вызывает Claude Vision
  своим ключом, списывает токены, возвращает результат.

## 5. Этапы реализации

1. **Аккаунты + бэкенд + платежи** — регистрация/вход, хранение статуса
   подписки и баланса токенов в БД, интеграция Stripe/Paddle.
2. **ИИ-эскиз через сервер** — прокси-эндпоинт с ключом Anthropic на
   сервере, списание токенов за вызов, перенос логики из `sketchAI.js`.
3. **Жёсткий гейт на документы** — перенос генерации из `export.js`/
   `cnc.js` на сервер, выдача файла только при активной подписке.
4. **UI оплаты** — экран входа, индикатор подписки и остатка токенов, окно
   оплаты/пополнения (правки в `app.js`/`ui-shell.js`, `index.html`).
5. **Проверка** — `code-reviewer` по каждому этапу, ручной прогон сценариев
   в браузере (без подписки/токенов — платные функции недоступны; с
   оплатой — доступны). Формулы конструктора не затрагиваются, поэтому
   `tools/smoke.js` не требуется, если Этап 1–4 не трогает `engine.js`.

## 6. Открытые вопросы (решаются по ходу Этапа 1, не блокируют старт)

- Выбор конкретного провайдера (Stripe vs Paddle) и юрисдикции для
  регистрации приёма платежей.
- Цена подписки и стоимость токена/вызова эскиза.
- Стартовый бесплатный запас токенов при регистрации.
- Хостинг для нового сервера (сейчас есть только статический GitHub Pages
  под текущее приложение — для бэкенда нужен отдельный хостинг).
